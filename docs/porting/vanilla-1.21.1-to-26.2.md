# MCHeli: vanilla API changes from 1.21.1 to 26.2 (Fabric port checklist)

The paths below are relative to `neoforge-1.21.1/src/main/java/mcheli/dependent/`.

**How this was checked.** Each change comes from the NeoForge primers at `https://github.com/neoforged/.github/blob/main/primers/<ver>/index.md`, which exist for 1.21.2, 1.21.4, 1.21.5, 1.21.6, 1.21.7, 1.21.8, 1.21.9, 1.21.10, 1.21.11, 26.1 and 26.2. There is no separate primer for 1.21.3; 1.21.2 covers it. Every item marked **[26.2 ✔]** was also confirmed with `javap` against the real 26.2 jar at `~/.gradle/caches/fabric-loom/26.2/minecraft-merged.jar` (Mojang names, unobfuscated). Fabric API class names come from the Fabric API jars in `~/.gradle/caches/modules-2/files-2.1/net.fabricmc.fabric-api/`. Those jars compile against `GuiGraphicsExtractor` and `Identifier`, so they are a 26.x build, but I did not confirm they are the exact 26.2 release.

**Re-checked on 2026-10-11 with `javap` against the 26.2 jars:** `EntityDataSerializers.COMPOUND_TAG` is gone; `MultiBufferSource` is gone; `Level.isClientSide()` is a method; the current screen is reached through `Minecraft.gui.screen()`; `Entity.moveOrInterpolateTo(...)` is final (`lerpTo` no longer exists); `OrderedSubmitNodeCollector.submitCustomGeometry(PoseStack, RenderType, CustomGeometryRenderer)` exists; `GuiGraphicsExtractor.fill(...)` has `RenderPipeline` overloads. Also see the verified table at the top of [`neoforge-to-fabric.md`](neoforge-to-fabric.md).

## 1. Entity rendering / render state

Sources: primers [1.21.2 §Entity Render States](https://github.com/neoforged/.github/blob/main/primers/1.21.2/index.md), [1.21.9 §Feature Submissions](https://github.com/neoforged/.github/blob/main/primers/1.21.9/index.md), [26.1 §Solid and Translucent Features](https://github.com/neoforged/.github/blob/main/primers/26.1/index.md), [26.2 §Feature Rendering: The Takeover](https://github.com/neoforged/.github/blob/main/primers/26.2/index.md), and the [Fabric 1.21.2 post](https://fabricmc.net/2024/10/14/1212.html) and [Fabric 1.21.9 post](https://fabricmc.net/2025/09/23/1219.html).

- [ ] **1.21.2**: `EntityRenderer<T>` became `EntityRenderer<T, S extends EntityRenderState>`. You implement `createRenderState()` and override `extractRenderState(T, S, float partialTick)`. `render` no longer receives the entity or its yaw.
  - Affected: all `client/*Renderer.java`. `MchModelEntityRenderer.render()` reads `configName()`, `skinTextureName()`, `xRotO/getXRot`, `getRollAngle/getPrevRollAngle`, `recoilPitchDeg/RollDeg`, `isDestroyed()`, `pilot()`, `hostInfo()`, `turretOrbitYaw`, `barrelSpin`, `weaponOperator(...)` (it reads the *operator* entity's rotations), `isMissilePartHidden`, `firstPersonHiddenGroups()`. Each of these must be copied into a `MchVehicleRenderState` during extract. The per-weapon turret math (lines ~310-360) needs its inputs snapshotted as well.
- [ ] **1.21.2**: `getTextureLocation(T)` was removed from the `EntityRenderer` base class. Texture choice now happens in the subclass from the state. Affected: `MchModelEntityRenderer`, `MchBulletRenderer`, and the other renderers.
- [ ] **1.21.2**: `Entity#getBoundingBoxForCulling` and `noCulling` moved to `EntityRenderer#getBoundingBoxForCulling(T)` / `affectedByCulling(T)`. **[26.2 ✔]** (protected). Affected: `entity/AbstractMchVehicle.java:1251`. The override must move into the renderer.
- [ ] **1.21.9**: `render(S, PoseStack, MultiBufferSource, int light)` became `submit(S, PoseStack, SubmitNodeCollector, CameraRenderState)`. **[26.2 ✔]**. Light now lives on the state (`EntityRenderState.lightCoords`, unverified field name).
- [ ] **1.21.9 / 26.2**: For custom meshes use `collector.submitCustomGeometry(PoseStack, RenderType, CustomGeometryRenderer)`, where `CustomGeometryRenderer.render(PoseStack.Pose, VertexConsumer)`. **[26.2 ✔]**. The lambda runs later, during the feature render phase, so **every input it captures must be immutable or copied**: the model reference, the colour, and the hidden-group sets. `MchModelRenderer.render*` already take `(PoseStack.Pose → last, VertexConsumer)` internally, so they can be wrapped almost unchanged. Rewrite them to take a `PoseStack.Pose` instead of a `PoseStack`. Animated parts (rotors, turrets) need one `submitCustomGeometry` per transform, or must pre-multiply their own matrices.
- [ ] **1.21.2 → 1.21.9**: `ModelPart.render(pose, consumer, light, overlay)` used immediately became `collector.submitModelPart(ModelPart, PoseStack, RenderType, light, overlay, TextureAtlasSprite)`. **[26.2 ✔]**. Affected: `MchBulletRenderer` (the tracer cube via `LayerDefinition.create(...).bakeRoot()`). `LayerDefinition`/`MeshDefinition` are unchanged per the 1.21.2 primer.
- [ ] **26.2**: The `MultiBufferSource` interface was removed ([26.2 primer, line 991](https://github.com/neoforged/.github/blob/main/primers/26.2/index.md)), so every `buffers.getBuffer(...)` call has to go. Affected: `MchModelEntityRenderer`, `MchBulletRenderer`, `MchCartridgeRenderer`, `MchContainerRenderer`, `VehicleItemRenderer`.
- [ ] **26.1**: Features render in separate solid and translucent passes. `ModelFeatureRenderer` sorts translucent submissions by camera distance. The single blended hull pass is fine as long as you pick a translucent `RenderType`; see §2.
- [ ] **Hiding the rider (NeoForge `RenderLivingEvent.Pre`)**: there is no vanilla hook. Use a mixin on `EntityRenderer#shouldRender`/`LivingEntityRenderer` or on extract. Fabric has `InvalidateRenderStateCallback` and `RenderStateDataKey`/`FabricRenderState` for attaching data to vanilla states, but no "cancel render" event (unverified). Affected: `client/MchRiderRenderHider.java`.
- [ ] **Renderer registration**: `EntityRendererRegistry.register(type, Ctx -> renderer)` from Fabric rendering-v1. Affected: `client/MchClientEvents.java` (`EntityRenderersEvent`).
- [ ] **World-render events**: Fabric removed `WorldRenderEvents` in 1.21.9 ([blog](https://fabricmc.net/2025/09/23/1219.html)). The 26.x jar has `client.rendering.v1.level.LevelRenderEvents` and `LevelExtractionEvents`. The module does not seem to use world-render hooks directly.

## 2. Model and vertex rendering (RenderType, RenderPipeline, VertexConsumer, PoseStack)

Sources: primers [1.21.2 §Shader Rewrites](https://github.com/neoforged/.github/blob/main/primers/1.21.2/index.md), [1.21.5 §Render Pipeline Rework](https://github.com/neoforged/.github/blob/main/primers/1.21.5/index.md), [1.21.11 §The RenderType Shuffle](https://github.com/neoforged/.github/blob/main/primers/1.21.11/index.md), [26.1 §Even More Rendering Changes](https://github.com/neoforged/.github/blob/main/primers/26.1/index.md), [26.2 §Too Many Rendering Changes](https://github.com/neoforged/.github/blob/main/primers/26.2/index.md).

- [ ] **1.21.2**: `RenderType.entityTranslucentCull` was **removed**. 26.2 has no `RenderTypes.entityTranslucentCull` **[26.2 ✔]**. The options are:
  - (a) `RenderTypes.entityTranslucentCullItemTarget(Identifier)`, whose semantics are unverified. It targets the item render target, so it is probably wrong for world entities.
  - (b) `RenderTypes.entityTranslucent(Identifier)`, which has no backface cull.
  - (c) A custom `RenderType.create(name, RenderSetup.builder(RenderPipelines.ENTITY_TRANSLUCENT_CULL).withTexture("Sampler0", id).useLightmap().useOverlay().createRenderSetup())`. `RenderPipelines.ENTITY_TRANSLUCENT_CULL` exists **[26.2 ✔]**, and the builder is per the 1.21.11 primer.
  - Affected: `client/MchModelEntityRenderer.java:155`. **Option (c) is recommended because it keeps the glass-alpha behaviour.**
- [ ] **1.21.11**: The built-in render types moved from `RenderType.*` to `net.minecraft.client.renderer.rendertype.RenderTypes.*`, and `RenderType` itself moved to `.rendertype.RenderType`. `RenderStateShard`/`CompositeState` were replaced by `RenderSetup`. **[26.2 ✔]**
- [ ] **26.1**: `entityCutoutNoCull` became `entityCutout` (the culled variant is now `entityCutoutCull`). **[26.2 ✔]**. Affected: `MchBulletRenderer` (twice), `VehicleItemRenderer`, `MchCartridgeRenderer`, `MchContainerRenderer` (check each).
- [ ] **26.2**: `VertexFormat.Mode` became `PrimitiveTopology`, and `DefaultVertexFormat` uses dynamic attributes. Entity pipelines still use `QUADS` per the primer example. `MchModelRenderer`'s "triangle becomes a degenerate quad" trick stays valid as long as the chosen pipeline is QUADS. Not verified for a custom `RenderSetup`; check the pipeline's `primitiveTopology`.
- [ ] **VertexConsumer** **[26.2 ✔]**: `addVertex(PoseStack.Pose, float, float, float)`, `setColor(int, int, int, int)`, `setColor(int argb)`, `setUv`, `setOverlay`, `setLight` and `setNormal(PoseStack.Pose, float, float, float)` all still exist. **`MchModelRenderer.emitVertex` compiles unchanged.** Changes at 1.21.11 and 26.1 only affect the `Vector3f` overloads (now `Vector3fc`) and `putBulkData` (now `putBakedQuad` with `QuadInstance`), neither of which is used here.
- [ ] **1.21.5**: `PoseStack.mulPose(Quaternionf)` now takes a `Quaternionfc` (source compatible). `PoseStack.Pose` gained translate, rotate and scale methods. `Axis.*.rotationDegrees` is unchanged (unverified in 26.2, but `com.mojang.math.Axis` is still used by vanilla).
- [ ] **1.21.5**: `RenderSystem` state calls became `RenderPipeline`/`GpuDevice`. The module does not import `RenderSystem`, so there is no direct impact.
- [ ] **26.1**: `GpuDevice`, `CommandEncoder` and `RenderPass` became wrappers around `*Backend`. **26.2**: Vulkan backend, `BlendFactor`, `GpuFormat`, `BindGroupLayout`. These only matter if you write custom `RenderPipeline`s. Option (c) above reuses a vanilla pipeline, so none of this applies.
- [ ] `OverlayTexture.NO_OVERLAY` and packed light `0xF000F0` are unverified in 26.2 but very likely unchanged.

## 3. GUI and HUD drawing

Sources: primers [1.21.2 §Gui Render Types](https://github.com/neoforged/.github/blob/main/primers/1.21.2/index.md), [1.21.6 §GUI Changes](https://github.com/neoforged/.github/blob/main/primers/1.21.6/index.md), [26.1 §Gui Extractor and §Container Screen Changes](https://github.com/neoforged/.github/blob/main/primers/26.1/index.md), [26.2 §Gui Reorganization](https://github.com/neoforged/.github/blob/main/primers/26.2/index.md), and the [Fabric 1.21.6 post](https://fabricmc.net/2025/06/15/1216.html) and [Fabric 26.1 post](https://fabricmc.net/2026/03/14/261.html).

- [ ] **1.21.2**: `blit` takes a render-type function first, and `setColor` was removed. **1.21.6**: that argument became a `RenderPipeline`, giving `blit(RenderPipelines.GUI_TEXTURED, Identifier, x, y, u, v, w, h, [rw, rh,] texW, texH)` **[26.2 ✔]**. Affected: `NeoHudRenderer.texture()` (`g.blit(rl, 0, 0, w, h, u, v, uw, vh, texW, texH)`) and `MchVehicleScreen` (lines 171 and 182).
- [ ] **1.21.6**: `GuiGraphics.pose()` returns a `Matrix3x2fStack`, so use `pushMatrix()/popMatrix()/translate(x, y)/rotate(radians)`. `PoseStack`, `Axis.ZP` and the z-translate no longer apply. Affected: `NeoHudRenderer.pushMatrix/popMatrix/texture`.
- [ ] **1.21.6**: `bufferSource()`, `drawSpecial` and `RenderType.gui*` were removed. Custom quads need their own `GuiElementRenderState` record implementing `buildVertices(VertexConsumer)`, `pipeline()` (`RenderPipelines.GUI`), `textureSetup()` (`TextureSetup.noTexture()`, unverified name), `scissorArea()` and `bounds()`. **`buildVertices` has no pose argument in 26.2 [26.2 ✔]**, so store a `Matrix3x2f` copy and call `vc.addVertexWith2DPose(matrix, x, y).setColor(argb)`. Submit it with `GuiRenderState.addGuiElement(...)` **[26.2 ✔]**. `GuiGraphicsExtractor.guiRenderState` is **private** **[26.2 ✔]**, so an accessor is needed. Affected: `NeoHudRenderer.segment()`, `line()`, `lineStipple()`. Alternatively, approximate lines with `fill(RenderPipeline, …)` on a rotated `Matrix3x2fStack`; fills respect the pose.
- [ ] **1.21.6**: `drawString` colours must include alpha, and a value with A = 0 is **not drawn**. Affected: `MchVehicleScreen` passes `0xFFFFFF` and `0xFF0000` (lines 192, 196, 200, 207, 227); OR these with `0xFF000000`. Also check the `argb` values the agnostic HUD passes to `NeoHudRenderer.string()`.
- [ ] **1.21.6**: Rendering is split into a prepare phase and a render phase, with element ordering by strata, tree, pipeline and texture. Draw order between the HUD lines (custom pipeline) and the text may change. Use `nextStratum()` if needed.
- [ ] **26.1**: `GuiGraphics` became `GuiGraphicsExtractor`, with `drawString` → `text`, `drawCenteredString` → `centeredText`, `renderItem` → `item`, `renderOutline` → `outline` **[26.2 ✔]**. On screens, `renderBg` became `Screen#extractBackground(GuiGraphicsExtractor, mx, my, pt)`, `renderLabels` became `extractLabels`, and `render` became `extractRenderState` **[26.2 ✔]**. Affected: `NeoHudRenderer`, `MchHudOverlay`, `MchWrenchOverlay`, `MchVehicleScreen`.
- [ ] **26.1**: `AbstractContainerScreen.imageWidth/imageHeight` are **final** and set through `super(menu, inv, title, w, h)` **[26.2 ✔]**. Its `render` now calls `renderTooltip` itself, so don't override `render`. Affected: `MchVehicleScreen` (it overrides `render` at line 233 and probably assigns `imageWidth`).
- [ ] **26.1**: `ClickType` became `ContainerInput` in `slotClicked`/`clicked`. Check `MchVehicleScreen` and `menu/MchVehicleMenu`.
- [ ] **26.2**: `Minecraft.screen` became `Minecraft.gui.screen()`, and `setScreen` became `gui.setScreen` **[26.2 ✔]**. The HUD moved to the `Hud` class (`gui.hud`). Affected: `client/MchKeybinds.java:85`, `client/MchClientInput.java:52`, `client/MchClientRotation.java:48`.
- [ ] **HUD registration (Fabric)**: NeoForge `RegisterGuiLayersEvent`/`VanillaGuiLayers.CROSSHAIR` become `HudElementRegistry.attachElementAfter(VanillaHudElements.CROSSHAIR, id, HudElement)`, where `HudElement.extractRenderState(GuiGraphicsExtractor, DeltaTracker)` **[26.x jar ✔]**. `HudRenderCallback` was removed in 26.1. Hiding the crosshair (`RenderGuiLayerEvent.Pre` cancel) can use `HudElementRegistry.replaceElement(CROSSHAIR, …)`. Affected: `client/hud/MchHudOverlay.java`, `MchWrenchOverlay.java`.

## 4. Camera

Sources: primers [1.21.11 change list](https://github.com/neoforged/.github/blob/main/primers/1.21.11/index.md) (line 2720) and [26.1 §Camera State](https://github.com/neoforged/.github/blob/main/primers/26.1/index.md); javap of the 26.2 `Camera`.

- [ ] **1.21.11**: `Camera.setup` takes a `Level`, and getters became record-style (`getEntity` → `entity`). **26.1**: `setup` became `update(DeltaTracker)` ("not one-to-one"), with new `extractRenderState(CameraRenderState, float)`, `getFov` and `setEntity`. **[26.2 ✔]**: `update(DeltaTracker)`, `private alignWithEntity(float)`, `protected setRotation(float, float)`, `protected setPosition(Vec3)`, `protected move(float, float, float)`, `private getMaxZoom(float)`, `public xRot()/yRot()`, `public rotation()` (Quaternionf), `isDetached()`, `entity()`.
- [ ] The partial tick now comes from `getCameraEntityPartialTicks(DeltaTracker)`. `detached`/`reverse` are read from fields or options, not parameters. Retarget `@Inject(method="setup")` to `alignWithEntity` at TAIL, or to `update` at TAIL (unverified which is cleaner). `@Shadow getMaxZoom` still works because shadows can be private.
- [ ] **Roll**: vanilla has no `setRotation(y, p, roll)`. After `setRotation`, apply roll yourself by multiplying `rotation` (`Quaternionf`) with `rotateZ` and recomputing the `forwards/up/left` vectors (all private and final). The other route is to modify `CameraRenderState.orientation` in `extractRenderState`, or to inject in `GameRenderer.bobView`/`renderLevel`. Affected: `mixin/CameraMixin.java` (all three `setRotation(…, roll)` calls).
- [ ] `net.neoforged.neoforge.client.ClientHooks.getDetachedCameraDistance` is NeoForge-only. Use the vanilla `EntityAttributes.CAMERA_DISTANCE` path (unverified) or a constant of 4.0 times the scale.
- [ ] **26.1**: The FOV path changed (`Camera#getFov`, `tickFov`, `GameRenderer#getFov` reworked). The NeoForge `ViewportEvent.ComputeFov` needs a mixin. Affected: `client/MchGunnerView.java`. `RenderFrameEvent.Pre` (used by `client/MchClientRotation.java`) also needs a mixin or Fabric `ClientTickEvents`/`LevelRenderEvents`; check its timing relative to mouse handling.

## 5. Entity, data sync, save/load, damage, explosions

Sources: primers [1.21.2 change list](https://github.com/neoforged/.github/blob/main/primers/1.21.2/index.md), [1.21.5](https://github.com/neoforged/.github/blob/main/primers/1.21.5/index.md), [1.21.6 §Generic Encoding and Decoding](https://github.com/neoforged/.github/blob/main/primers/1.21.6/index.md), [1.21.9](https://github.com/neoforged/.github/blob/main/primers/1.21.9/index.md), [26.1 §Removal of interactAt and §Level#random](https://github.com/neoforged/.github/blob/main/primers/26.1/index.md), and the [Fabric 1.21.6 post](https://fabricmc.net/2025/06/15/1216.html) (tracked-data registry).

- [ ] **1.21.6**: `readAdditionalSaveData(CompoundTag)` and `addAdditionalSaveData(CompoundTag)` now take `ValueInput`/`ValueOutput`, with methods such as `getIntOr`, `getStringOr`, `read(key, codec)`, `store(key, codec, v)`, `childrenList`/`list`. **[26.2 ✔]**. Affected: `AbstractMchVehicle` (lines 1202-1235, including the seat `ListTag` of `{Id: UUID, Seat: int}`; store it with `UUIDUtil.CODEC` through a record codec), `MchHelicopter` (63-73), `MchContainer` (104-109; its inventory probably used `ContainerHelper`, check), and the empty overrides in `MchBullet`, `MchFlare` and `MchCartridge`.
- [ ] **1.21.5**: `CompoundTag.getX` returns `Optional`, `getXOr(key, def)` is new, `getUUID/putUUID/hasUUID` were removed, and `contains(key, type)` was removed. Affected: `AbstractMchVehicle:1719-1721` (`t.getInt(k)` on the synced seat tag) and any NBT kept in sync data.
- [ ] **1.21.9**: **`EntityDataSerializers.COMPOUND_TAG` was removed.** **[26.2 ✔]**: absent; `EntityDataSerializers.registerSerializer` is public. On Fabric, register through `FabricEntityDataRegistry.register(Identifier, EntityDataSerializer)` **[26.x jar ✔]**, using e.g. `EntityDataSerializer.forValueType(ByteBufCodecs.COMPOUND_TAG)` (unverified name). A cleaner option is two dedicated serializers: an int→int seat map and an ammo record. Affected: `AbstractMchVehicle:139-150, 748-749`.
- [ ] **1.21.2**: `Entity#hurt` became `final hurt(...)` that dispatches to `abstract boolean hurtServer(ServerLevel, DamageSource, float)` and `hurtClient(DamageSource)`. **[26.2 ✔]**. Affected: the `hurt` overrides in `AbstractMchVehicle`, `MchFlare` and `MchContainer`. The `victim.hurt(src, dmg)` calls in `MchExplosion`, `MchBullet` and `DemoHpSelfTest` still compile (the final `hurt` exists), but on the server prefer `hurtServer(level, …)`.
- [ ] **1.21.2**: `kill()` became `kill(ServerLevel)`, `spawnAtLocation` takes a `ServerLevel`, and `teleportTo` gained a `boolean`. `isInvulnerableTo` moved to `LivingEntity`. Grep: none of these are used in core entity code (check the self-tests).
- [ ] **1.21.5**: `lerpTo(x, y, z, yRot, xRot, steps)` became `final moveOrInterpolateTo(...)` plus `InterpolationHandler getInterpolation()` **[26.2 ✔ final]**. You can no longer override it to drop or accept interpolation. Override `getInterpolation()` instead: return `null` for "snap" (unverified default) or a custom `InterpolationHandler`. `moveTo` became `snapTo`, and `absMoveTo` became `absSnapTo`. Affected: `AbstractMchVehicle:1380`, `MchBullet:992` (the server-authoritative curved path depends on this), and `MchFlare:143`.
